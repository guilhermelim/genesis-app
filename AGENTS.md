# AGENTS.md - genesis-app

## Project Overview
Next.js 16 (App Router) + TypeScript + MongoDB/Mongoose + MUI v7. Clean Architecture / DDD structure.

## Commands
| Command | Purpose |
|---------|---------|
| `npm run dev` | Start dev server with Turbopack |
| `npm run build` | Production build |
| `npm run start` | Run production server |
| `npm run lint` | ESLint (extends next/core-web-vitals + next/typescript) |

## Architecture (high-signal facts)
- **Path alias**: `@/*` → `src/*` (tsconfig.json)
- **Domain layer** (`src/domain/`): entities, factories, repository interfaces — pure TS, no framework deps
- **Use cases** (`src/usecase/`): one folder per operation (create/list/find/update/delete), each with DTO + use case class
- **Infrastructure** (`src/infrastructure/`): MongoDB implementations under `infrastructure/<context>/repository/mongodb`, plus one context-specific Server Actions module
- **Server Actions** (`src/infrastructure/<context>/<context>.actions.ts`): Next.js adapters that instantiate the concrete repository and use case
- **UI**: MUI v7 with CSS variables theming, dark/light mode via `InitColorSchemeScript`

## Database
- MongoDB connection singleton in `src/lib/database.ts`
- Requires `DATABASE_URL` env var (defaults to `mongodb://root:secret@localhost:27017/genesis?authSource=admin`)
- Mongoose models in `src/infrastructure/*/repository/mongodb/model/`
- IDs are generated by domain factories and persisted as strings by MongoDB models

## Key Conventions
- Use cases receive repository **interface** in constructor (DI); context Actions instantiate concrete repositories
- Entities validate in constructor; throw `Error` on invalid state
- Server Actions: one module per context contains reads and mutations; typed inputs and use cases; mutations return serializable `ActionResult<T>` values and the UI unwraps them for explicit error handling
- React components: `"use client"` where needed; data is received through props

## Environment
- `.env.local` for `DATABASE_URL` (not committed)
- Jest with `ts-jest` is configured; tests use expressive `.test.ts`, `.unit.test.ts`, and `.integration.test.ts` suffixes. `npm test` runs the complete suite in one command. Domain, use case, action, and repository unit tests run without a database; the three MongoDB repository integration suites use the temporary Docker test database automatically.
- `npm run test:coverage` enforces 100% statements, branches, functions, and lines for the Node-testable domain, use case, infrastructure, and database layers

## Gotchas
- Turbopack enabled in dev (`next dev --turbopack`) — may differ from webpack behavior
- MUI v7 uses the App Router cache provider
- ESLint rule `@typescript-eslint/no-empty-object-type` set to error with `allowInterfaces: "always"`

## File Layout (mental model)
```
src/
├── app/                    # Next.js App Router pages and client page wrappers
├── components/             # Shared UI components
├── sections/               # Feature-specific UI sections (poll, activity, member)
├── domain/                 # Entities, factories, and repository interfaces
├── infrastructure/         # Context actions, MongoDB repositories, and models
├── lib/                    # Database connection and shared runtime helpers
├── usecase/                # Application use cases + DTOs
└── theme.ts                # MUI theme config
```
